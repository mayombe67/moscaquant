# Documentation guide

Start with the [project overview](../README.md) and [canonical roadmap](../ROADMAP.md). This guide routes readers to existing documents; it is not another status ledger.

## Scientific record

- [Charter](../CHARTER.md): governing question and authority.
- [Experiment index](experiments/README.md): protocols, result records and their provenance.
- [Experiment ledger](EXPERIMENT_LEDGER.md) and [known confounds](KNOWN_CONFOUNDS.md): recorded work and interpretation limits.
- [Experimental retrospective](retrospectives/MOSCAQUANT_EXPERIMENTAL_HIGHLIGHT_REEL.md): explanatory science/lore framing.

Frozen protocols and result records govern their own claims. A dated “next” instruction or historical test count is not a current execution request or a fresh validation result.

An interface's existence does not establish that a current subject is attached to it.

## Repository ownership

The [open-core boundary](OPEN_CORE_BOUNDARY_V1.md) and [component matrix](PUBLIC_PRIVATE_COMPONENT_MATRIX_V1.md) define what belongs here.

Public scientific contracts and evidence stay here. Provider-specific deployment, operational receipts and operator workflows belong to Ops. Product experience, production scenes and presentation deployment belong to Panopticon. Their operational backlogs should not be copied into this public guide.

## Supporting material

Oracle, achievement, personnel, observance and environment documents remain versioned references for their specific contracts. Presentation lore and historical deployment instructions are supporting material, not the primary scientific entry point. Consult their stated scope and date before treating a status statement as current.
